# PoC到底要怎么做

## PoC 的作用

这轮 PoC 的作用，是把项目从“可以演示”进一步推进到“有初步验证结果”。

当前最需要回答的问题有两类：

1. 人在借助原型后，是否能更快、更有依据地完成初步排查。
2. 原型是否具备把一次处理过程沉淀成案例，并在后续同类问题中继续使用的能力。

这轮 PoC 就围绕这两点展开。

## 这轮 PoC 的结构

当前 PoC 只保留两个必做部分：

1. 排障任务对照验证。
2. 案例回写复用验证。

第一部分是多人参与的现场执行，第二部分是项目组内部完成的流程验证。

## 第一部分：排障任务对照验证

### 目标

这一部分用于比较“人工查资料”和“人工借助原型”两种方式的差异，重点看三类结果：

1. 找到有效依据需要多久。
2. 输出是否有据可依。
3. 整体结果是否更完整、更适合作为初步排查依据。

### 基本配置

当前建议的现场配置如下：

1. 4 名测试者。
2. 1 名主持人。
3. 1 名计时记录员。
4. 1 名技术保障员。

如果人数有限，主持人和技术保障员可以由同一人兼任。

### 任务设置

当前按 4 个固定任务执行，覆盖两类设备：

1. T1：液压泵站压力波动且伴随异响。
2. T2：液压泵站油温连续偏高，冷却器状态正常。
3. T3：数控主轴单元振动异常且加工精度下降。
4. T4：数控主轴单元温升偏高并伴随异响。

每位测试者做 2 个任务，其中 1 个任务采用人工方式，1 个任务采用系统辅助方式。

### 现场流程

现场执行可以按下面顺序理解：

1. 先给测试者编号，发任务卡和答案卡。
2. 主持人统一说明规则。
3. 第 1 轮开始，计时记录员同步计时。
4. 测试者第一次定位到准备采用的依据时，举手或明确示意，记录员登记时间。
5. 8 分钟结束后收回答案卡。
6. 切换任务和模式后，进行第 2 轮。
7. 第 2 轮结束后，同步整理答案卡、时间记录和转录文本。

### 现场需要保留的原始材料

这部分执行完以后，至少要保留下列内容：

1. 测试者基础信息表。
2. 任务分配表。
3. 时间记录表。
4. 答案卡图片或扫描件。
5. 答案卡转录文本。

这些材料会直接用于后续 judge、结果汇总和 PPT。

## 第二部分：案例回写复用验证

### 目标

这一部分用于验证案例回写闭环是否成立，也就是一次处理过程回写进知识库以后，系统能否在后续同类问题中再次命中这条案例。

### 执行方式

这部分不需要重新组织测试者，项目组内部即可完成。建议流程如下：

1. 先选择一个当前有依据、但没有完整案例卡的任务。
2. 保留回写前的提问和检索截图。
3. 按模板补全处理步骤、最终结论和经验总结。
4. 完成回写并更新知识库。
5. 再次输入同类问题，保留命中新案例的截图。

### 需要保留的材料

这部分至少要留下下面几项：

1. 回写前问题截图。
2. 样本处置记录。
3. 新生成案例卡截图。
4. 回写后二次检索命中新案例的截图。

## 执行前需要准备什么

PoC 正式执行前，建议先把下面几项确认清楚：

1. 原型运行正常，使用固定版本。
2. 知识库状态已更新到统一版本。
3. 4 个任务的最终文本已经确认。
4. 任务卡、答案卡和总表已经准备好。
5. 现场负责技术保障的人已经确定。

这些准备工作决定的是现场是否顺畅，不只是流程是否完整。

## PoC 做完以后需要形成什么

PoC 完成后，建议尽快整理出下面四类结果：

1. 一张结果总表。
2. 一段简短的验证结论。
3. 一组案例回写前后截图。
4. 一份可直接交给后续材料整理人的原始包。

## 这一阶段各类组员分别做什么

### 非技术组员

非技术组员在这一阶段主要负责组织和整理工作，包括：

1. 约测试者。
2. 安排时间和场地。
3. 准备任务卡、答案卡和记录表。
4. 现场计时、收表和归档。
5. 整理结果表和截图。

### 技术组员

技术组在这一阶段主要负责支撑 PoC 的执行环境，包括：

1. 保证原型现场可用。
2. 准备知识库和任务样本。
3. 处理系统辅助环节的操作。
4. 配合整理 PoC 二所需的截图和案例路径。

## 一句话总结

这轮 PoC 的核心工作，是把现场执行、数据留存和结果整理接起来，最终形成一组能直接用于后续材料的验证证据。
