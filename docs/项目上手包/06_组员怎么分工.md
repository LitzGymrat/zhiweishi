# 组员怎么分工

## 分工的基本思路

这个项目后续工作的内容之间关联很强。PoC 结果会进入 PPT，PPT 会影响视频，视频和项目简介又会反过来影响计划书。因此，分工更适合按模块来拆，而不是按单个文件来拆。

## 一个比较清楚的分工方式

如果团队人数允许，可以按下面四块来安排：

1. PoC 执行。
2. 材料统稿。
3. PPT 与展示制作。
4. 原型与演示支持。

## PoC 执行这块负责什么

这一块主要负责把验证真正落地，工作内容包括：

1. 确定任务和测试者名单。
2. 安排时间、场地和流程。
3. 准备任务卡、答案卡和记录表。
4. 现场计时、收表和归档。
5. 整理结果总表、截图和验证结论。

这一块的核心交付是结果表和原始材料包。

## 材料统稿这块负责什么

这一块主要负责文字和口径，工作内容包括：

1. 写项目简介。
2. 整理项目定位和核心痛点表述。
3. 统一不同材料里的说法。
4. 后续扩展到计划书时继续统稿。

这一块的核心交付是稳定、可复用的文字版本。

## PPT 与展示制作这块负责什么

这一块负责把现有内容转换成更适合展示的形式，工作内容包括：

1. 搭 PPT 骨架。
2. 整理原型截图。
3. 画闭环图和流程图。
4. 把验证结果整理成表格或图表。
5. 配合视频脚本和录屏顺序。

这一块的核心交付是清楚、统一、便于展示的可视化材料。

## 原型与演示支持这块负责什么

这一块负责保证原型在关键节点上稳定可演示，工作内容包括：

1. 检查系统运行状态。
2. 准备知识库和样本任务。
3. 支撑 PoC 中的系统辅助环节。
4. 准备录屏和答辩使用的演示路径。

这一块的核心交付是稳定的演示环境。

## 如果团队人数不多

如果人数有限，也可以压缩成三类角色：

1. 一人负责 PoC 执行和结果整理。
2. 一人负责项目简介、计划书和统稿。
3. 一人负责原型支持、PPT 和视频演示。

最后再由负责人统一检查口径和交付顺序。

## 非技术组员适合承担哪些内容

非技术组员通常更适合承担下面这些工作：

1. PoC 组织和现场流程。
2. 测试者协调和签到记录。
3. 原始材料归档。
4. 项目简介和计划书文字整理。
5. PPT 页面逻辑和版式配合。

## 技术组员适合承担哪些内容

技术组员更适合承担：

1. 原型维护。
2. 数据和任务准备。
3. 演示路径控制。
4. PoC 中的系统支持和问题处理。

## 协作时要注意什么

后续协作里，比较关键的是几个交接点：

1. PoC 执行完成后，结果表和截图要及时交给统稿和 PPT 负责人。
2. 项目简介和 PPT 的核心表述确认后，再继续做视频脚本。
3. 原型截图和演示路径确定后，再进入录屏环节。

## 一个简单的协作节奏

后续推进时，保持一个简短的同步节奏会比较有效。每次沟通只需要确认三件事：

1. 现在已经完成了什么。
2. 还有什么待确认。
3. 下一步由谁在什么时间交付什么。

## 一句话总结

后续分工的核心，是让 PoC、文字材料、展示材料和原型支持形成接力关系，而不是彼此分散推进。
