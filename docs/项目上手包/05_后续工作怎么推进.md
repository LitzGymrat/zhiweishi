# 后续工作怎么推进

## 当前阶段的判断

项目现在已经进入“把现有成果组织成完整参赛作品”的阶段。原型部分已经有基础，后续工作的重点是验证、材料和表达顺序。

## 推荐的推进顺序

后续工作建议按下面顺序推进：

1. 先完成 PoC。
2. 再整理项目简介。
3. 再搭 PPT 骨架。
4. 再准备视频脚本和录屏。
5. 最后再扩写创业计划书。

这个顺序的原因很简单：每一步都在为下一步提供稳定素材。

## PoC 之后先做什么

PoC 完成后，第一步不是马上做展示，而是先把结果整理成可用材料。建议先确认下面几项已经形成：

1. 结果总表。
2. 案例回写前后截图。
3. 简短验证结论。
4. 可交给后续写作者和制作者使用的原始包。

这一步完成后，后面的项目简介和 PPT 会顺很多。

## 项目简介怎么接

项目简介适合紧接在 PoC 之后完成，因为它需要用非常短的篇幅讲清楚下面四件事：

1. 项目解决的是什么问题。
2. 为什么这个问题真实存在。
3. 方案由哪些部分组成。
4. 当前已经做到哪一步，并验证了什么。

如果这四件事已经通过 PoC 和前期文档稳定下来，项目简介就不会来回改动太多。

## PPT 怎么接

PPT 适合建立在项目简介和 PoC 结果之上。当前比较稳定的骨架可以按下面几部分来搭：

1. 问题定义。
2. 调研和背景依据。
3. 解决方案和工作闭环。
4. 原型演示。
5. PoC 验证结果。
6. 落地路径。

有了这个骨架，后面视频和计划书都更容易展开。

## 视频怎么接

视频本质上是“项目简介 + PPT 主线 + demo 录屏”的组合，因此更适合放在 PPT 之后。此时需要的准备主要包括：

1. 固定讲述顺序。
2. 固定 demo 路径。
3. 固定录屏节点和截图。

这样做的好处是，视频不会反复返工。

## 两周内的一个简单推进节奏

如果按一到两周安排，可以参考下面这个节奏：

1. 第 1 阶段：2 到 3 天内完成 PoC 和结果整理。
2. 第 2 阶段：1 到 2 天完成项目简介和 PPT 主骨架。
3. 第 3 阶段：1 到 2 天完成视频脚本、录屏顺序和展示材料整理。
4. 第 4 阶段：在前面内容稳定后继续扩展计划书。

## 当前最值得先完成的三件事

如果只看接下来最值得优先完成的内容，可以先盯住这三件事：

1. 跑完 PoC。
2. 形成正式项目简介。
3. 搭出 PPT 的核心页面。

这三项一旦完成，整套项目的主线就比较稳定了。

## 对组员来说如何理解这段工作

对组员来说，后续工作可以理解为两步：

1. 先把项目价值和验证结果固定下来。
2. 再把这些内容转成不同形式的比赛材料。

## 一句话总结

后续推进的核心，不是同时做很多事，而是按顺序把 PoC、项目简介、PPT、视频和计划书接起来。
