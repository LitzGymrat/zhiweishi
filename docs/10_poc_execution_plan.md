# 校园环境轻量PoC落地方案（仅保留两个必做PoC）

## 一、本文用途

本文用于把当前原型从“可以演示”推进到“在校园环境里也能落地执行、并产出验证证据”。

本轮 PoC 只保留两个必做项：

1. 排障任务对照验证。
2. 案例回写复用验证。

验证口径保持收敛，不做“AI 替代人工”的表述，只回答两个问题：

1. 人工借助原型后，是否比单纯人工查资料更快、更容易形成有依据的初步排查结果。
2. 原型是否具备把一次处理过程沉淀为案例，并在后续同类问题中再次调用的能力。

## 二、校园版执行原则

为了方便在校园里落地，本方案统一按以下原则执行：

1. 不依赖企业现场，不要求真实工厂停机或真实产线操作。
2. 只使用当前知识库中已经有依据的设备、文档和故障任务，不临时扩题。
3. 测试者以校内同学、老师、研究生、实验室设备管理员为主，不强求企业维修人员到场。
4. 所有结论统一写成“小样本场景验证”或“校园样本验证”，不夸大为产业化效果。
5. 案例回写部分允许使用“样本处置记录”做模拟验证，但必须明确标注为 PoC 样本案例，不能冒充真实企业维修记录。

## 三、校园最小执行配置

### 1. 推荐时间安排

推荐按“半天准备 + 一个下午执行 + 1 到 2 小时整理”来安排：

1. 准备阶段：2 到 3 小时。
2. 执行阶段：约 2 小时。
3. 整理阶段：1 到 2 小时。

如果你们时间很紧，两个 PoC 可以在同一天下午完成。

### 2. 推荐场地与设备

校园环境下，下面这些条件就足够：

1. 一间普通教室、实验室或会议室。
2. 1 台主持人电脑，用于运行 Streamlit 原型和投屏。
3. 4 台测试者电脑，或让测试者自带笔记本。
4. 1 个统一的原始资料文件夹，用于人工条件检索。
5. 1 个计时工具，可以直接用手机秒表。
6. 纸质或电子记录表。

### 3. 推荐人员配置

校园版最小配置如下：

1. 4 名测试者。
2. 1 名主持与计时人员。
3. 1 名记录与评分人员。

如果实在凑不齐 4 名测试者，最低可以 3 人先跑通流程，但正式材料里仍建议尽量做到 4 人以上。

测试者来源建议优先按下面顺序找：

1. 机械、自动化、能源、材料等相关专业同学。
2. 做过工厂实习、金工实习或实验室设备管理的同学。
3. 研究生、相关老师或实验室设备管理员。
4. 项目组之外、但能理解设备场景的同学。

建议至少一半测试者不来自项目核心成员。

### 4. 固定任务包

为了减少准备成本，校园版直接固定为 4 个任务，不再扩展到 6 个任务。优先使用当前知识库中已经能找到依据的任务：

| 任务编号 | 设备 | 任务描述 | 当前可直接使用的依据 | 建议用途 |
| --- | --- | --- | --- | --- |
| T1 | 液压泵站 | 压力波动且伴随异响 | 说明书 + SOP + 点检日志 + 维修工单 + 历史案例 | PoC 一 |
| T2 | 液压泵站 | 油温连续偏高，冷却器状态正常 | 说明书 + SOP | PoC 一 / PoC 二 |
| T3 | 数控主轴单元 | 振动异常且加工精度下降 | 说明书 + SOP + 点检日志 + 维保班报 + 维修记录 + 历史案例 | PoC 一 |
| T4 | 数控主轴单元 | 温升偏高并伴随异响 | 说明书 + SOP | PoC 一 / PoC 二 |

原则很简单：

1. T1 和 T3 用来做“资料较全”的对照验证。
2. T2 或 T4 用来做“原本没有完整案例卡”的回写复用验证。
3. 本轮不再引入“润滑报警频发”这类当前资料支撑不够稳的任务。

## 四、必做PoC一：排障任务对照验证

### 1. 验证目标

PoC 一只回答一个具体问题：

面对典型设备异常，测试者在使用“智维师”辅助后，是否能更快找到依据，并给出更完整、更规范的初步排查结果。

### 2. 校园版最小设计

为了方便落地，校园版不采用复杂的大样本设计，而是采用“4 名测试者、每人 2 个任务、每人 1 次人工 + 1 次系统”的轻量交叉方式。

推荐直接使用下面这个分配矩阵：

| 测试者 | 第 1 个任务 | 第 2 个任务 |
| --- | --- | --- |
| P1 | T1 人工 | T3 系统辅助 |
| P2 | T1 系统辅助 | T3 人工 |
| P3 | T2 人工 | T4 系统辅助 |
| P4 | T2 系统辅助 | T4 人工 |

这样设计的好处是：

1. 每名测试者只做 2 个任务，执行负担低。
2. 每名测试者都经历 1 次人工和 1 次系统，材料更容易写。
3. 两类设备都被覆盖，叙事更完整。

### 3. 单任务规则

每个任务统一按下面规则执行：

1. 任务时长控制在 8 分钟内。
2. 两个任务之间留 2 分钟切换时间。
3. 人工条件下允许查看原始资料文件夹、文件名搜索、文档内关键词查找。
4. 人工条件下不允许直接看原型输出结果。
5. 系统条件下允许使用当前原型、原型返回的依据文档和结构化排障卡。
6. 所有测试者都必须填写同一张答案卡，避免最后输出格式无法比较。

本轮 PoC 不做重记录，只保留最后能进 PPT 的最小数据集。

### 4. 建议使用的答案卡

每个任务只要求测试者填写 3 项，够评分即可：

| 字段 | 说明 |
| --- | --- |
| 关键依据 | 写出 1 到 2 条文件名或文档标题 |
| 建议排查步骤 | 写 3 条左右即可 |
| 风险或停机建议 | 写 1 条即可 |

像“可能原因”“长段分析”“完整参考文档列表”这些内容，不纳入 PoC 记录表，因为它们对最终 PPT 的价值不高，容易徒增负担。

这张答案卡同时也是后续 LLM-as-judge 的输入，不再额外整理一版长答案。

### 5. 记录方式与 LLM-as-judge 流程

校园环境下，不再由记录人员现场逐项打分，而是采用“一张任务参考卡 + 一个固定 judge prompt + 同一模型批量判分”的方式。

建议主持人提前为 4 个任务各做 1 张“任务参考卡”。每张参考卡只保留下列三类内容：

1. 本任务允许命中的关键依据文件。
2. 本任务至少应出现的 2 到 3 个核心排查动作。
3. 本任务至少应出现的 1 条风险或停机边界。

PoC 一的建议流程如下：

1. 测试者现场填写统一答案卡。
2. 主持人或记录人员只负责计时和收集答案，不做质量评分。
3. 活动结束后，把“任务描述 + 任务参考卡 + 测试者答案”喂给同一个 judge 模型统一打分。
4. 全部样本必须使用同一模型、同一 prompt、同一温度设置，建议温度固定为 0 或 0.1，避免口径漂移。
5. 只对低分样本或明显异常样本做一次人工抽查，不再全量人工复评。

如果条件允许，judge 模型尽量不要与原型生成答案使用同一个模型；如果做不到，也至少要保证 judge 与生成链路的 prompt 完全分开。

建议 judge 输出固定 JSON：

```json
{
	"grounding_appropriate": true,
	"score": 4,
	"final_judgement": "correct",
	"reason": "引用了有效文档，排查步骤基本完整，并给出了明确停机边界。"
}
```

字段含义建议统一如下：

1. `grounding_appropriate`：是否真正基于给定依据作答，取 `true` 或 `false`。
2. `score`：综合质量分，取 1 到 5 分。
3. `final_judgement`：结论标签，建议只用 `correct`、`partially_correct`、`incorrect` 三档。
4. `reason`：一句话解释原因，供后续抽查和答辩举例使用。

建议 judge prompt 只做一件事：判断答案是否基于给定依据、是否覆盖关键动作和风险边界，不评价语言是否华丽。

为了严格贴合最终材料，本轮只记录 3 个核心指标：

| 指标 | 取值方式 | 判定说明 |
| --- | --- | --- |
| 首次定位到有效依据时间 | 秒 | 参与者第一次明确指出可用文档时记时 |
| LLM判定有据可依 | 0 / 1 | 由 `grounding_appropriate` 转换，`true=1`，`false=0` |
| LLM综合得分 | 1 到 5 | 直接使用 judge 的 `score` |

这 3 个指标正好对应最后最容易写进 PPT 的 3 句话：

1. 是否更快找到资料。
2. 是否更有据可依。
3. 输出是否更规范、更适合初步排查。

像“总完成时间”“完成率”“拆开的步骤分与风险分”，如果你们人手紧，就不再单独记录。

如果要继续降低工作量，`final_judgement` 和 `reason` 不进入总表，只在原始 judge 结果里留存。

### 7. 结果判定建议

PoC 一不需要做复杂统计，满足下面 3 条里的 2 条即可支撑“排障辅助有价值”的结论：

1. 系统辅助组平均资料定位时间更短。
2. 系统辅助组的 `LLM判定有据可依` 比例更高。
3. 系统辅助组的 `LLM综合得分` 平均值更高。

最后写进 PPT 时，也只建议保留这 3 类结果，不再展开每个测试者的过程细节。

## 五、必做PoC二：案例回写复用验证

### 1. 验证目标

PoC 二只验证一件事：

系统能否把一次处理过程沉淀成案例卡，并在后续同类问题中再次命中这条案例。

### 2. 人员要求说明

PoC 二和 PoC 一不同，它不需要再组织一批测试者。

更直接地说：

1. PoC 二可以由项目组内部独立完成。
2. 不要求再找 4 名参与者。
3. 不要求再做一轮对照测试。

推荐的最小配置是：

1. 1 名操作人：负责提问、回写、更新索引、截图。
2. 1 名复核人：负责确认样本处置记录完整性，并做回写前审核。

如果时间特别紧，技术上 1 个人也能把流程跑通；但为了后续答辩更稳，材料里仍建议保留“2 人完成内部复核”的口径。

### 3. 推荐任务

校园环境下，推荐优先选 T2 或 T4，因为这两类任务当前有说明书和 SOP 支撑，但没有现成的完整历史案例卡，更容易把“回写前”和“回写后”的差异展示出来。

如果只做 1 组验证，优先推荐：

1. T2：液压泵站油温连续偏高，冷却器状态正常。

### 4. 校园版执行步骤

为了避免污染正式演示知识库，PoC 二按下面步骤执行：

1. 先备份 `prototype/data/documents/case_cards/`、`prototype/data/chroma_db/` 和 `prototype/data/bm25_index.json`。
2. 在回写前先提问一次，并保存问题截图。
3. 由项目组根据现有说明书和 SOP，整理一份“样本处置记录”。
4. 样本处置记录至少要填满“实际处理步骤”“最终结论”“经验总结”三项，不能留空。
5. 样本处置记录提交前，至少由 2 人确认：1 名项目成员 + 1 名非核心测试者、老师或相关专业同学。
6. 完成确认后，再通过原型执行案例回写和索引更新。
7. 用同一故障的相近表述再次提问，保存新案例被命中的截图。
8. PoC 结束后，如果不想影响正式演示环境，再把备份恢复回去。

### 5. 回写前审核清单

PoC 二在校园里最容易翻车的点，是把没填完整的自动案例直接写进知识库。所以回写前必须做一次审核。

| 审核项 | 通过标准 |
| --- | --- |
| 实际处理步骤 | 至少 3 条，且是可执行动作 |
| 最终结论 | 至少 1 句完整结论，不能写“待补充” |
| 经验总结 | 至少 1 条可复用经验 |
| 依据来源 | 优先来自说明书、SOP、日志、维修记录，不把自动案例当作唯一依据 |
| 命名方式 | 建议统一加 `POC_` 前缀，便于后续识别和清理 |

只要有一项不满足，就不要执行回写。

### 6. 校园版样本处置记录建议写法

为了减少现场发挥，建议你们在 PoC 前先准备一个模板，现场只做少量修改。示例模板如下：

```text
实际处理步骤：
1. 复核油温读数，并确认冷却器工作状态。
2. 检查回油状态、过滤器状态和油液清洁度。
3. 在低负荷状态下复测油温变化，确认是否继续上升。

最终结论：
当前温升问题与散热效率或回油状态异常相关，继续运行前应先停机复核。

经验总结：
当油温持续高于阈值且冷却器表面状态正常时，不能只盯冷却器本体，还应同步检查回油与过滤状态。
```

这段只是样本模板，最终内容要以你们实际选定的任务和依据文档为准。

### 7. 必须保存的证据

PoC 二只保留最后最有展示价值的 4 项证据：

1. 回写前问题截图。
2. 样本处置记录截图。
3. 回写生成的新案例卡截图。
4. 回写后再次提问命中新案例的截图。

不再额外要求保存大量中间过程图，也不单独整理长说明文档。最后的解释文字，直接合并到 PPT 的验证页文案里即可。

### 8. PPT中的推荐表达

建议写成：

“在校园样本验证中，我们选取一类当前有说明书和 SOP 支撑、但缺少完整案例卡的故障任务，完成了人工确认后的案例回写。结果显示，回写后的新案例能够在后续相近问题检索中被再次命中，说明原型已具备经验沉淀与复用能力。”

## 六、当天执行顺序建议

如果你们要在一个下午内跑完，建议直接按下面顺序执行：

1. 先完成环境检查和任务卡、答案卡发放，10 分钟。
2. 再做 PoC 一第 1 轮任务，8 分钟。
3. 切换任务与方式，2 分钟。
4. 做 PoC 一第 2 轮任务，8 分钟。
5. 当场整理 PoC 一记录表，并导出 LLM judge 所需输入，15 到 20 分钟。
6. 再做 PoC 二回写前提问、样本处置记录确认和回写，20 到 30 分钟。
7. 最后做回写后再次检索、截图，并统一跑 LLM judge 导出结果，10 到 15 分钟。

这样安排的好处是：

1. 人员集中一次到场即可。
2. 两个 PoC 的证据可以在同一天拿齐。
3. 当天就能整理成 PPT 需要的表格和截图。

## 七、PoC结束后的最小成果包

只要你们最后整理出下面 4 样东西，就已经足够支撑挑战杯材料：

1. 一张任务对照结果总表。
2. 一张 3 指标对比图，分别是资料定位时间、LLM判定有据可依比例、LLM综合得分。
3. 一组案例回写前后截图。
4. 一段 100 到 150 字、可直接贴进 PPT 的验证结果总结。

除此之外，不再追求更厚的过程材料。

## 八、建议直接写进材料的验证结论模板

下面这段可以在拿到真实结果后直接替换数据：

“我们在校园环境下围绕液压泵站和数控主轴单元选取了 4 个已有资料支撑的典型任务，组织 4 名测试者开展了两项必做 PoC。结果显示，在人工借助原型辅助的条件下，测试者在资料定位速度、LLM-as-judge 判定的有据可依比例和综合得分方面整体优于单纯人工查阅资料。进一步地，我们完成了 1 组样本案例回写复用验证，证明系统已具备将处理经验沉淀并在后续相近问题中再次调用的能力。”
