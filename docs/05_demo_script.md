# Demo与答辩脚本

## 一、演示目标

让评委在3到5分钟内理解三件事：

1. 为什么这是东北传统制造业升级中的一个具体课题，而不是泛化AI选题
2. 为什么我们的方案不是单点问答，而是围绕排障、培训和经验沉淀构建的工作闭环
3. 为什么当前原型已经具备概念验证价值，并能继续走向本地部署和实际应用

## 二、演示定位

演示不是为了展示作品的全部内容，而是为了用一条最核心的业务链，证明项目已经超越概念阶段，具备“实际需求导向 + 原理样机 + 可继续扩展”的基础。

## 三、演示故事线

### 场景设定

某东北中小制造企业存在一台老旧设备，相关知识分散在说明书、SOP和历史维修记录中。值班人员遇到异常时，需要快速定位问题；新员工同时也需要尽快掌握该设备的常见故障知识。

### 演示目标

用一次故障排查过程，展示系统如何同时完成知识检索、排障辅助、培训生成和经验沉淀，并说明这套原型如何对应东北制造业数智赋能中的真实应用需求。

## 四、建议使用的演示样本

1. 设备说明书1份
2. SOP文档1份
3. 常见故障表1份
4. 历史维修记录2份
5. 自整理案例卡10到20条

## 五、演示步骤

### 演示前30秒开场

建议先用一句话把比赛要求和项目定位扣住：

我们聚焦的不是泛化工业大模型平台，而是东北中小制造企业老旧设备维保这一具体课题，尝试用知识增强方式解决“资料分散、经验依赖、培训慢、案例难沉淀”的现实问题。

### 步骤1：导入资料

展示设备说明书、SOP和历史案例已经进入系统，说明知识库构成真实且可解释。

### 步骤2：输入故障问题

示例问题：

液压系统压力波动且伴随异响，应该先检查什么？

### 步骤3：展示结构化排障卡

重点展示：

1. 可能原因
2. 建议排查顺序
3. 风险提示
4. 依据文档
5. 是否建议停机或上报

讲述重点：

这里要强调系统输出的是结构化辅助结果，而不是一段泛泛的聊天文本；它的价值在于帮助一线人员更快找到依据并规范初步排查。

### 步骤4：切换到培训模式

生成该设备常见故障速查卡和5道测试题，说明系统不仅解决当前故障，还能帮助新人学习。

讲述重点：

这里要说明项目并不只解决“这一次排障”，还在解决“老师傅经验如何更快传给新人”这一长期问题。

### 步骤5：演示案例回写

将本次处理结果整理为新的案例卡并写入知识库，说明系统具备经验沉淀能力。

讲述重点：

这里要强调你们的创新点在于把排障、培训和经验沉淀做成闭环，这比单次问答更贴近企业真实工作流。

### 结尾30秒落点

建议最后明确三件事：

1. 当前原型已经完成单设备、单故障场景下的概念验证。
2. 下一步可以从单车间扩展到更多设备和更多班组。
3. 项目的落地价值在于用低成本、本地化方式帮助中小制造企业先完成知识和流程的数字化升级。

## 六、答辩时的讲述重点

1. 我们不是做泛化工业大模型平台，而是聚焦东北中小制造企业老旧设备维保场景。
2. 我们不是要替代专家，而是帮助现场人员更快地找到依据、更规范地做初步排查。
3. 我们的创新点在于排障、培训和经验沉淀的一体化闭环，而不是堆砌技术名词。
4. “智维师”不是全部作品本身，而是整套解决方案中的核心原理样机和应用入口。

## 七、展示时要避免的表述

1. 不要说本系统可以完全替代老师傅。
2. 不要说东北所有企业都存在完全相同的问题。
3. 不要把多Agent当成必须卖点，除非演示里真的体现出清晰分工价值。
4. 不要把作品讲成单一功能产品，要始终回到“东北具体课题 + 解决方案 + 原理样机 + 落地路径”的结构。
