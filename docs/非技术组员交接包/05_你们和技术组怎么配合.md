# 你们和技术组怎么配合

## 各自负责什么

当前比较清楚的分工方式是：

1. 技术组负责让原型稳定、可运行、可展示。
2. 你们负责把 PoC、结果整理和后续材料推进起来。

这两部分不是互相替代，而是前后接力。

## 你们这边主要需要掌握什么信息

虽然你们不负责代码和系统实现，但有几项信息需要尽早和技术组确认：

1. PoC 当天使用哪个固定版本的原型。
2. 当前最终确认的 4 个任务是什么。
3. PoC 二使用哪个任务做案例回写复用验证。
4. 现场由谁负责技术保障。
5. 原型截图和输出结果后续如何保存和交接。

这些信息一旦固定，PoC 的组织会清楚很多。

## 和技术组沟通时，什么样的信息更有效

和技术组沟通时，尽量把需求说成明确的交付，而不是泛泛地提支持。例如可以直接确认：

1. 哪一天做 PoC。
2. 需要哪个固定页面入口。
3. 任务列表什么时候确认。
4. 哪位同学负责现场技术保障。
5. 哪些截图节点需要保留。

这种方式更容易让后续准备一次性到位。

## PoC 阶段的配合方式

PoC 阶段比较适合按下面方式配合：

1. 你们负责人、时间、场地、流程、记录表和结果整理。
2. 技术组负责原型运行、任务环境、系统辅助环节和现场问题处理。

这样现场分工会比较清楚。

## PoC 做完以后怎么继续配合

PoC 做完以后，下一步的关键是把结果继续接成材料。这时建议继续从技术组这里拿到几项内容：

1. 可用于 PPT 的原型截图。
2. 一段简短的原型说明文字。
3. 当前确认过的闭环逻辑或结构图。
4. 一段落地路径的技术侧说明。

你们再把这些内容整理成更适合比赛材料使用的表达。

## 后续协作里容易出的问题

后续比较常见的问题主要有三类：

1. 结果和截图没有及时交接。
2. 不同材料的口径不一致。
3. 材料推进和技术确认的时间点没有对齐。

这些问题如果提前意识到，后面就比较好处理。

## 一个简单的协作节奏

后续沟通不需要太复杂，保持一个简短节奏就可以。每次沟通只需要确认三件事：

1. 现在已经确定了什么。
2. 还有什么待确认。
3. 下一步由谁在什么时间交付什么。

## 这一份的结论

你们和技术组的配合关系，可以理解成前后接力：技术组把原型和现场环境稳定下来，你们把 PoC、结果整理和后续材料继续接起来。
