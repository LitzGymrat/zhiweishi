# 轻量PoC执行方案

## 一、本文用途

本文用于把当前原型从“可以演示”推进到“有验证证据支撑”。

这里的 PoC 不是做论文式模型实验，而是做一组围绕真实工作流的小样本场景验证，证明三件事：

1. 人工单独查资料和人工借助原型之间，效率是否有差异。
2. 原型输出的结果是否更容易形成有依据、较规范的初步排查结论。
3. 案例回写后，系统是否真的形成了可复用的知识闭环。

本项目最合适的验证口径不是“AI 替代人工”，而是“人工 + 原型”是否比“单纯人工查资料”更快、更稳、更容易沉淀经验。

## 二、当前最值得做的PoC，不需要做得很重

如果你们时间有限，建议把验证压缩为“两项必做 + 一项可选”。

### 1. 必做一：排障任务对照验证

目标：证明系统在故障排查辅助上确实有现实价值。

### 2. 必做二：案例回写复用验证

目标：证明系统不是一次性回答，而是能把处理过程沉淀进知识库。

### 3. 可选三：培训模式可用性反馈

目标：补充说明系统对新人学习和班组培训也有帮助。

如果你们只完成前两项，其实已经足够支撑比赛中的“概念验证”表达。

## 三、建议采用的最简配置

### 1. 人员配置

建议至少准备以下角色：

1. 4 到 6 名测试者。
2. 1 名主持与计时人员。
3. 1 名记录人员。

测试者的来源建议优先按这个顺序找：

1. 机械、自动化、材料、能源等相关专业同学。
2. 有工厂、车间、实习经历的同学。
3. 相关方向老师、研究生或实验室设备管理员。
4. 项目组之外、但能理解设备场景的人。

建议至少一半测试者不来自项目核心成员，这样可信度更高。

### 2. 场景配置

建议继续沿用当前原型中的两类设备族：

1. 液压泵站。
2. 数控主轴单元。

每类设备准备 3 个典型任务，共 6 个任务即可，不需要再扩充很大。

### 3. 材料配置

建议直接使用当前原型里已有的：

1. 说明书。
2. SOP。
3. 巡检或维修记录。
4. 历史案例卡。
5. 原型系统当前知识库。

这样做的好处是验证和演示用的是同一套样本，材料不会分裂。

## 四、必做PoC一：排障任务对照验证

## 1. 验证目标

回答一个非常具体的问题：

面对典型设备异常，使用“智维师”辅助后，测试者能不能更快找到依据、给出更完整的初步排查结果。

## 2. 推荐设计

为了避免同一个人先做人工、再做系统导致学习效应太重，建议采用 A/B 交叉方式。

### 任务准备

从现有测试集中选 6 个任务，按难度分成 A、B 两组，每组 3 个任务。

建议示例：

1. 液压泵站压力波动伴异响。
2. 液压泵站启动后压力建立缓慢。
3. 液压泵站油温偏高。
4. 数控主轴单元温升异常。
5. 数控主轴单元振动增大。
6. 数控主轴单元润滑报警频发。

最终任务以你们当前原型测试集中真实存在的任务为准。

### 分组方式

1. 将测试者分为两组。
2. 第一组先做 A 组人工任务，再做 B 组系统辅助任务。
3. 第二组先做 B 组人工任务，再做 A 组系统辅助任务。

### 人工条件

人工条件下允许使用：

1. 原始 PDF 或整理后的文档文件夹。
2. 文件名搜索。
3. 文档内关键词查找。

人工条件下不允许直接使用原型输出结果。

### 系统条件

系统条件下允许使用：

1. 当前“智维师”原型。
2. 原型返回的依据文档。
3. 原型生成的结构化排障卡。

### 单任务时间限制

建议每个任务控制在 8 到 10 分钟以内。超过上限仍未完成的，记为“未完成”。

## 3. 建议记录指标

建议至少记录下面 6 个指标：

| 指标 | 记录方式 | 用途 |
| --- | --- | --- |
| 首次定位到有效依据时间 | 从开始到找到第一条可用依据的时间 | 证明资料定位效率 |
| 完成初步排查结论总时间 | 从开始到提交答案的时间 | 证明整体完成效率 |
| 是否找到明确依据 | 0 或 1 | 证明输出是否有据可依 |
| 步骤完整度 | 1 到 5 分 | 证明排查流程是否规范 |
| 风险提示充分性 | 1 到 5 分 | 证明结果是否更适合现场使用 |
| 是否完成任务 | 完成或未完成 | 证明可操作性 |

## 4. 建议使用的记录表

| 测试者编号 | 任务编号 | 设备类型 | 方式 | 首次依据定位时间 | 总完成时间 | 是否找到依据 | 步骤完整度 | 风险提示 | 是否完成 | 备注 |

| P1 | T1 | 液压泵站 | 人工 |  |  |  |  |  |  |  |
| P1 | T4 | 数控主轴 | 系统辅助 |  |  |  |  |  |  |  |

## 5. 结果判定建议

你们不需要做复杂统计，只需要把结果写清楚。

建议用下面这种判断方式：

1. 系统辅助组平均资料定位时间更短。
2. 系统辅助组平均完成时间更短，或完成率更高。
3. 系统辅助组在“有依据”“步骤完整”“风险提示”上平均分更高。

只要能得到以上三类结果中的两类，就足够支撑“排障辅助有价值”的结论。

## 五、必做PoC二：案例回写复用验证

## 1. 验证目标

证明系统不是只会一次性回答，而是真的能把处理经验沉淀下来，并在下次同类问题中被再次使用。

## 2. 推荐做法

建议按下面 5 步执行：

1. 先选一个当前知识库中没有完整案例卡、但已有相关文档依据的故障任务。
2. 用原型完成一次排障和案例回写。
3. 保存回写前的检索结果截图。
4. 让系统更新知识库。
5. 再输入同类或相近表述的问题，保存回写后的检索结果截图。

## 3. 需要保存的证据

建议至少保存以下内容：

1. 回写前问题截图。
2. 回写前依据列表截图。
3. 新生成的案例卡截图。
4. 回写后再次检索时命中新案例的截图。
5. 一段简短说明，解释“这证明了什么”。

## 4. PPT中的推荐表达

建议写成：

“在一次故障处理后，系统可将人工确认后的处理过程整理为案例卡并回写知识库；在后续同类问题检索中，新案例能够被再次命中，说明原型已具备经验沉淀与复用能力。”

## 六、可选PoC三：培训模式可用性反馈

如果你们还有余力，再补这一项即可；如果时间紧，这项可以弱化。

## 1. 验证目标

证明培训模式不只是展示功能，而是对新人学习有一定帮助。

## 2. 最简做法

1. 选一个设备主题，例如“液压泵站常见压力异常”。
2. 用系统生成一张培训速查卡和 5 道练习题。
3. 找 4 到 6 名测试者阅读速查卡并完成练习题。
4. 收集他们对理解难度、内容清晰度和学习帮助度的评分。

## 3. 建议反馈问题

采用 5 分制即可：

1. 这张速查卡是否比直接翻原始资料更容易理解。
2. 这组练习题是否有助于记住常见故障点。
3. 该模式是否适合用于新人上岗前快速熟悉设备。

## 七、PoC执行后的最小成果包

只要你们最后能整理出下面 5 样东西，就已经足够支撑比赛材料：

1. 一张任务对照结果总表。
2. 一张平均分或平均时间对比图。
3. 一页小样本反馈总结。
4. 一组案例回写前后截图。
5. 一段 150 字左右的验证结论。

## 八、建议直接写进材料的验证结论模板

下面这段建议在拿到真实结果后按数据替换：

“我们围绕液压泵站和数控主轴单元选取了 [6] 个典型任务，组织 [4 到 6] 名测试者开展小样本场景验证。结果显示，在人工借助原型辅助的条件下，测试者在资料定位速度、初步排查完成效率和结果规范性方面整体优于单纯人工查阅资料。进一步地，我们完成了 1 组案例回写复用验证，证明系统已具备将处理经验沉淀并在后续同类问题中再次调用的能力。”

## 九、执行顺序建议

建议你们按下面顺序做，不要一上来就剪视频：

1. 先定 6 个任务。
2. 再定测试者名单。
3. 再做任务对照验证。
4. 接着做回写复用验证。
5. 最后整理图表和一句话结论。

做到这一步，你们的原型就不只是“能演示”，而是有了真正能写进 PPT、计划书和视频里的验证证据。
