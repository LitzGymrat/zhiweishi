# 竞赛定位与项目落地框架

## 一、本文用途

本文用于把“智维师”从一个可演示的原型，进一步上升为符合“挑战杯”中国大学生创业计划竞赛东北振兴产业升级专项赛要求的完整参赛项目。

重点回答三个问题：

1. 为什么本项目贴合“数智赋能产业”赛道要求。
2. 为什么“智维师”不只是一个产品，而是一套面向东北具体课题的解决方案。
3. 为什么当前原型已经具备概念验证基础，并能继续走向落地和商业计划。

## 二、与比赛要求的对应关系

根据专项赛方案，项目需要同时满足“东北具体课题”“实践研究”“解决方案或原理样机”“具备概念验证和商业计划意愿”四个层面。本项目可按以下方式对应：

1. 东北具体课题：聚焦东北中小制造企业老旧设备维保中的知识分散、经验依赖、新人培训慢和案例难沉淀问题，属于传统制造业改造提升中的真实应用课题。
2. 实践研究：以政策材料、产业案例、企业公开资料、小样本访谈或问卷、样本设备文档整理为依据，不空谈“工业大模型平台”。
3. 解决方案与原理样机：当前已经形成本地可运行原型，具备文档导入、故障排查、培训支持、案例回写和知识库更新闭环。
4. 概念验证与商业计划：项目可以从单企业、单车间、单类设备切入，逐步扩展为轻量化本地部署与知识服务方案，具备创业计划书可写性。

## 三、项目不应只被理解为“一个产品”

在参赛叙事中，“智维师”不应只被理解为一个问答界面，而应被理解为一套完整方案中的核心工作台。

完整作品应包含五层：

1. 问题层：东北传统制造业数智化升级过程中，老旧设备维保仍存在知识断层和经验依赖。
2. 机制层：构建“资料治理 - 结构化排障 - 培训支持 - 案例沉淀 - 知识更新”的工作闭环。
3. 产品层：用原型系统把上述闭环做成可交互、可演示、可验证的工具。
4. 验证层：通过样本任务、对照测试、问卷反馈和案例回写效果，说明系统的实际价值。
5. 落地层：明确谁来用、何时用、怎么部署、怎么维护、如何持续积累知识并形成服务模式。

因此，比赛中应避免把整套项目讲成“我们做了一个工业聊天机器人”。更合适的表述是：

本项目针对东北中小制造企业老旧设备维保中的具体痛点，提出一套知识增强智能辅助方案；“智维师”是这套方案的核心原理样机和应用入口。

## 四、推荐的完整项目结构

### 1. 问题研究包

用于证明项目不是概念空转，而是建立在东北产业升级现实课题之上。

建议包含：

1. 东北制造业数字化、智能化升级的政策背景。
2. 设备维保、技能传承、知识沉淀不足的行业或企业案例。
3. 小样本访谈、问卷或场景观察，证明一线人员确实存在“查资料慢、依赖老师傅、案例难复用”的痛点。

### 2. 解决方案设计包

用于说明你们不是堆技术名词，而是围绕实际工作流程做设计。

建议突出：

1. 知识来源是真实维保材料，而非泛化互联网文本。
2. 输出是结构化排障卡、培训卡和复盘建议，而不是单段聊天文本。
3. 回写后的案例会进入知识库，形成持续更新机制。

### 3. 原型系统包

用于承担“原理样机”的角色。

当前原型可以支撑以下展示：

1. 分类测试集构建。
2. 故障排查卡生成。
3. 培训模式生成。
4. 案例回写与知识库重建。

### 4. 验证评估包

用于把“能跑”上升为“有价值”。

建议优先准备以下验证：

1. 人工查手册与系统辅助在耗时上的对比。
2. 输出完整度、依据引用率、步骤规范性等结构化指标。
3. 新员工培训场景中的主观可用性反馈。
4. 案例回写后是否能在下一次检索中被命中和复用。

### 对“实验”的处理建议

这个项目需要验证，但不建议把验证写成偏论文式的“模型实验”。对创业计划竞赛来说，更合适的说法是“小样本场景验证”或“概念验证”。

建议把验证控制在以下范围：

1. 任务对照：选 5 到 10 个典型故障任务，对比人工查资料和系统辅助在耗时、资料定位和步骤完整度上的差异。
2. 结构化评分：围绕“是否引用依据”“步骤是否完整”“风险提示是否合理”“表达是否规范”设 3 到 5 个评分项，做小样本评分。
3. 使用反馈：结合访谈或问卷，收集一线人员、相关专业同学或老师对可用性和价值感知的反馈。
4. 回写复用：展示一次案例回写后，系统在后续同类问题中能够再次命中该案例。

不建议投入过多精力去做以下内容：

1. 大规模模型对比实验。
2. 复杂算法消融实验。
3. 统计显著性检验。
4. 超出当前样机能力的产业化量化承诺。

在 PPT、简介和计划书中，优先使用“调研”“验证”“概念验证”“场景验证”这些表述，不必频繁使用“实验”一词，以免把作品带向学术论文叙事。

### 5. 落地与创业包

用于满足创业计划竞赛对“概念验证”和“商业计划”的预期。

建议写法：

1. 目标客户：东北装备制造、石化、冶金、材料等领域中设备资料分散、数字化基础较弱的中小企业。
2. 切入方式：先从单企业单车间的典型设备入手，不追求一次覆盖全厂。
3. 交付形态：本地部署的知识辅助系统，加上文档整理、案例沉淀和培训支持服务。
4. 收费思路：知识库初始化服务费 + 年度维护费 + 培训服务费。
5. 扩展方向：从设备维保扩展到岗位培训、安全巡检、工艺知识问答等相邻场景。

## 五、项目的现实落地点

本项目的落地点不应写成“全面改变制造业”，而应写成更具体、更可信的三步：

1. 先解决单一设备族的知识碎片化问题，让一线人员更快找到依据、规范做初步排查。
2. 再解决班组层面的培训和经验沉淀问题，把老师傅经验逐步结构化、文档化、可复用化。
3. 最后才考虑向更多设备、更多车间、更多企业复制。

对应到你们当前项目，可以明确写为：

1. 当前样本聚焦液压泵站和数控主轴单元。
2. 当前功能聚焦排障、培训和回写闭环。
3. 当前目标是验证“低成本知识增强工具能否在老旧设备维保场景中产生实际辅助价值”。

这个落点足够窄，也足够真，更符合本科团队在专项赛中的可信边界。

## 六、答辩时应该如何定义创新点

建议把创新点收敛到“场景化、闭环化、低成本”三点，而不是强调模型规模或多智能体本身。

建议表述：

1. 场景化：聚焦东北中小制造企业老旧设备维保，不做泛化工业平台。
2. 闭环化：把故障排查、培训支持和经验沉淀做成一个连续工作流。
3. 低成本：不依赖重型工业改造，而是从知识和流程数字化切入，更适合中小企业采用。

## 七、建议准备的参赛材料结构

### 1. 500字项目简介

重点写：

1. 东北具体课题是什么。
2. 你们的解决方案是什么。
3. 原型已经验证了什么。
4. 未来怎样落地。

### 2. 创业计划书

建议主线：

1. 产业背景与痛点。
2. 用户画像与使用场景。
3. 解决方案与系统闭环。
4. 技术路线与原型样机。
5. 验证结果与应用价值。
6. 落地路径与服务模式。
7. 团队分工与实施计划。

### 3. 20页以内PPT

建议重点放在：

1. 真实问题。
2. 场景切入。
3. 解决方案。
4. 原型演示。
5. 验证结果。
6. 落地模式。

### 4. 支撑材料

建议优先准备：

1. 公开政策和行业材料摘录。
2. 小样本访谈或问卷结果。
3. 演示样本文档目录。
4. 原型截图与结构图。
5. 典型案例回写前后效果说明。

## 八、当前阶段最值得补的不是新功能，而是新证据

从你们目前进展看，原型已经够支撑答辩，不应继续无止境加功能。当前最值得补的是：

1. 一组更像真实班组工作流的小样本验证。
2. 一份更明确的落地实施路径。
3. 一套创业计划赛视角下的商业与推广表述。

如果这三项补上，整套项目就不再只是“一个做得不错的 demo”，而会更像“一个围绕东北产业升级具体课题提出的解决方案型作品”。
