# 技术设计说明

## 一、MVP目标

MVP不追求做成泛化工业智能平台，只需要在本地跑通一条完整链路：

1. 文档导入
2. 故障提问
3. 证据检索
4. 结构化排障输出
5. 培训题生成
6. 案例回写

## 二、系统边界

### 当前MVP解决的问题

1. 设备维保资料检索慢
2. 故障排查步骤不成体系
3. 新员工学习材料不集中
4. 排障经验难以沉淀

### 当前MVP不解决的问题

1. 实时工业控制
2. 复杂预测性维护
3. 传感器时序建模
4. 多工厂统一调度

## 三、核心功能模块

### 1. 知识库构建模块

输入材料：

1. 设备说明书
2. SOP与巡检规范
3. 常见故障案例
4. 培训资料
5. 历史维修记录

处理流程：

1. 文档解析
2. 文本切分
3. 标签化
4. 向量化存储

### 2. 故障排查辅助模块

输入：

1. 设备名称
2. 异常现象
3. 可选补充信息，如温度异常、异响、振动、漏油等

输出：

1. 可能原因
2. 建议排查顺序
3. 风险提示
4. 文档依据
5. 是否建议上报或停机

### 3. 培训学习模块

1. 自动生成岗位速查卡
2. 自动生成常见故障问答
3. 自动生成基础测试题

### 4. 案例回写模块

1. 记录故障现象
2. 记录实际处理步骤
3. 记录最终结论
4. 人工确认后写回知识库

## 四、推荐技术架构

### 前端

1. Streamlit 或 Gradio

### 后端

1. Python
2. 文档解析：PyPDF、docx2txt、pandas、openpyxl
3. OCR增强：rapidocr-onnxruntime 或同类轻量方案

### 检索与知识增强

1. 向量库：Chroma
2. Embedding：BGE中文向量模型
3. 检索链路：关键词过滤 + 向量检索

### 生成层

1. 兼容API模型或本地模型
2. 建议优先保留可切换能力，不把架构绑定在单一模型上

## 五、核心数据流

1. 文档进入系统
2. 系统解析并切分文档
3. 文本块进入知识库
4. 用户输入故障问题
5. 系统做问题分类并检索相关内容
6. 系统输出结构化排障卡
7. 用户确认后将案例写回知识库

## 六、结构化输出模板

建议统一输出如下字段：

1. 故障现象
2. 可能原因
3. 建议排查步骤
4. 风险提示
5. 依据文档
6. 建议处理级别

## 七、建议优先实现顺序

### 第一阶段

1. 跑通本地演示界面
2. 准备2到3个设备样本
3. 手动整理10到20条典型故障案例

### 第二阶段

1. 接入真实文档解析
2. 接入向量检索
3. 接入结构化生成模板

### 第三阶段

1. 完成案例回写
2. 完成培训模式
3. 优化界面与答辩演示

## 八、可展示的指标

1. 检索命中率
2. 结构化回答完整度
3. 典型故障处理耗时对比
4. 新员工学习效率提升的主观问卷结果
5. 案例回写后的复用次数
