# PoC材料包说明（实验与记录版）

## 用途

默认前提：

1. 网站已经部署在公网服务器上，测试者直接用浏览器访问。
2. 执行组这边要做的是实验、记录和归档。

所以这份材料包重点放在资料和记录上，不放代码、环境配置、Docker、API Key 和启动脚本。

## 使用人

1. 负责组织 PoC、发任务卡、控场和收表的同学。
2. 负责记时间、整理截图、汇总 judge 输入输出和归档结果的同学。

## 先统一口径

本轮 PoC 记录两件事：

1. 测试者用系统辅助后，能不能更快找到依据，并整理出更完整的初步排查结果。
2. 一次处理过程回写成案例后，后面能不能再次检索到这条案例。

结论统一写成“小样本验证”或“校园场景验证”。


## 材料包里不要放什么

网站已经在公网服务器上运行，材料包里不要放这些内容：

1. `app.py`、`src/`、`Dockerfile`、`requirements.txt` 这类代码文件。
2. `.env`、API Key、服务器配置和部署脚本。
3. 本地启动脚本、隧道脚本、开发环境说明。
4. 和实验记录无关的整套代码目录。

按资料包和记录包整理即可，不要做成部署包。

4. `03_记录与回收/`：当天必须收回来的所有底稿。

## PoC 必带文档清单

### A. 最少要放进包里的规则文档

材料包放入：

1. `01_project_brief.md`：项目是什么、边界是什么。
2. `10_poc_execution_plan.md`：PoC 的验证目标、任务设计和指标口径。
3. `12_poc_onsite_execution.md`：现场怎么组织、怎么计时、怎么归档。

执行组时间很紧的话，也至少先读这三份。

### B. PoC 一原始资料

PoC 一要比较“人工查资料”和“系统辅助”两种方式，人工模式资料一定要准备完整。

#### 液压泵站任务组

对应 T1、T2，建议至少放下面 6 份原始资料：

1. `液压泵站维护手册_整理版.md`
2. `液压泵站点检SOP.md`
3. `液压泵站点检日志_202603.csv`
4. `液压泵站维保班报_20260316.md`
5. `液压泵站维修工单_20260316.md`
6. `HC-002_吸油接头进气案例.md`

任务对应：

1. T1“压力波动且伴随异响”用上述 6 份资料。
2. T2“油温连续偏高，冷却器状态正常”重点用手册和 SOP，日志与工单作为补充。

#### 数控主轴单元任务组

对应 T3、T4，建议至少放下面 6 份原始资料：

1. `数控主轴维护手册_整理版.md`
2. `数控主轴开机与点检SOP.md`
3. `数控主轴点检日志_202603.csv`
4. `数控主轴维保班报_20260320.md`
5. `NC-004_主轴振动维修记录.md`
6. `NC-004_主轴振动案例.md`

任务对应：

1. T3“振动异常且加工精度下降”用上述 6 份资料。
2. T4“温升偏高并伴随异响”重点用手册和 SOP，日志作为补充背景。

### C. PoC 二回写资料

PoC 二资料放这 4 项：

1. 选定任务的简短说明。
2. 一份样本处置记录模板。
3. 一张回写前后截图清单。
4. 一份回写审核清单。

PoC 二保存这 4 项证据：

1. 回写前提问截图。
2. 样本处置记录截图。
3. 回写生成的新案例卡截图。
4. 回写后再次提问命中新案例的截图。

### D. 不要混进人工资料包的内容

PoC 一人工查阅资料文件夹里不要放这些内容：

1. `data/real_data/` 里的背景论证材料。
2. PPT、简介、宣传文案。
3. judge 输出结果。
4. 已经整理好的总结性结论。

人工模式资料包里只放原始知识资料，不要提前塞结论。

## 记录和实验开展指引

### 一、会前准备

现场开始前，先完成这 6 件事：

1. 确认公网网站地址可访问，口令可用。
2. 确认测试者编号表、任务分配表、答案卡、计时总表已经准备好。
3. 确认人工模式原始资料文件夹已经单独整理好。
4. 确认记录人员知道“第一次定位到有效依据”怎么记。
5. 确认 PoC 二的样本处置记录模板和截图清单已经备好。
6. 确认当天归档目录已经建好，避免现场资料散落。

### 二、PoC 一怎么记

PoC 一现场统一按同一套口径记录。

每个任务最少记录这些字段：

1. 测试者编号。
2. 任务编号。
3. 设备类型。
4. 执行方式，人工或系统辅助。
5. 首次定位到有效依据时间。
6. 测试者最终答案。
7. 备注，是否超时、卡住或出现明显异常。

答案卡建议只保留三个作答字段：

1. 关键依据。
2. 建议排查步骤。
3. 风险或停机建议。

不要让测试者自由发挥写长文，不然现场难收，后面也难统一喂给 judge。

### 三、PoC 二怎么记

PoC 二不需要再组织一批测试者，把回写前后证据链记完整即可。

最少记录这些内容：

1. 选的是哪个任务。
2. 回写前页面返回了什么。
3. 样本处置记录由谁填写、由谁复核。
4. 回写后生成了哪张案例卡。
5. 回写后相近提问是否再次命中该案例。

PoC 二不需要长报告，只留截图、记录和复核信息。

### 四、活动结束后必须回收什么

活动结束后，至少回收这 5 组底稿：

1. 测试者编号表和任务分配表。
2. PoC 一答案卡原件或转录文本。
3. PoC 一计时总表。
4. PoC 二回写前后截图和样本处置记录。
5. judge 输入与输出文件。

统一归档到：

```text
PoC结果包/
  01_admin/
  02_poc1_raw/
  03_poc2_raw/
  04_summary/
```

### 五、最容易漏掉的地方

现场最容易漏掉的是：

1. 只记了总耗时，没记第一次定位到依据时间。
2. 保存了截图，但没保存原始答案卡或转录文本。
3. 做了回写演示，但没有留回写前后同题对比截图。

## 一句结论

PoC 材料包尽量做轻，把这三样东西带齐就够了：

1. 原始知识资料。
2. 实验开展指引。
3. 当天要回收的记录底稿模板和归档口径。
