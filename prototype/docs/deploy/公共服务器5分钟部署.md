# 公共服务器 5 分钟部署

这份说明只保留一条最短路径：把当前原型部署到一台公共 Linux 服务器上，让别人直接通过浏览器访问。

## 适合什么情况

适合下面这种场景：

1. 你不想让组员自己装环境。
2. 你希望大家通过一个固定网址或公网 IP 访问。
3. 当前只需要 PoC1 只读体验，不需要开放案例回写。

如果你是接手部署任务的组员，建议先看 [部署组员交接说明.md](./部署组员交接说明.md)，那份更短。

## 当前推荐方案

当前最推荐的是：

1. 用 Docker 在服务器上启动。
2. 默认跑 `PoC1 只读模式`。
3. 在 `.env` 中设置 `access_password`。

这样配置最少，也最稳。

## 部署前准备

服务器上先确保有：

1. Docker
2. `docker compose`
3. 一个可对外访问的公网 IP 或域名

## 第一步：把项目传到服务器

把整个 `prototype/` 目录传到服务器，例如放到：

```bash
/opt/zhiweishi-prototype
```

## 第二步：准备 `.env`

在服务器上进入项目目录后，先准备 `.env`：

```bash
cp server.env.example .env
```

然后至少把下面几项填好：

```bash
deepseek_api_key=你的DeepSeek Key
qwen_api_key=你的Qwen Key
PUBLIC_APP_MODE=poc1_readonly
access_password=你自己设定的访问口令
```

`access_password` 很重要。因为这是公网访问，不建议裸开放。

如果你需要完整配置项，再回头参考 `.env.example`。

## 第三步：启动服务

在服务器项目目录执行：

```bash
chmod +x deploy_public_server.sh
./deploy_public_server.sh
```

这一步会自动：

1. 构建镜像
2. 启动容器
3. 检查本地知识库索引是否存在
4. 如果索引不存在，先自动建库再启动页面

## 第四步：访问地址

启动成功后，直接访问：

```text
http://你的服务器IP:8506
```

或者你自己的域名：

```text
http://你的域名:8506
```

首次访问会先看到口令页，输入 `access_password` 才能进入。

## 第五步：开放防火墙端口

如果页面打不开，通常先检查防火墙和安全组，确保开放：

```text
TCP 8506
```

## 常用命令

启动：

```bash
docker compose -f compose.public.yml up -d --build
```

查看日志：

```bash
docker compose -f compose.public.yml logs -f
```

停止：

```bash
docker compose -f compose.public.yml down
```

## 当前建议

如果只是给组员试用，这套“公共服务器 + PoC1 只读 + 访问口令”的组合，已经够用了。

后面如果你真的要长期公开访问，再考虑：

1. 域名
2. HTTPS
3. 反向代理
4. 更细的访问控制
