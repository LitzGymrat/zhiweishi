# 部署组员交接说明

这份说明只对应一个任务：把当前原型部署到一台公共 Linux 服务器上，让其他人通过浏览器访问。

如果你是负责服务器部署的组员，优先看这一份，不需要先通读整个项目文档。

## 你拿到的应该是什么

最省事的交付方式不是整个工作区，而是部署包。

如果项目负责人已经帮你打好包，你拿到的通常会是一份类似下面这样的压缩包：

```text
zhiweishi_server_handoff_时间戳.zip
```

如果他直接把整个仓库给你，也没关系，你实际只需要用 `prototype/` 目录。

## 你部署时默认目标是什么

当前默认目标不是完整写入版，而是：

1. `PoC1 只读模式`
2. 公网可访问
3. 有访问口令
4. 浏览器直接打开

也就是说，你不需要先折腾本地开发环境，不需要自己跑 `uv sync`，优先走 Docker 这一条最短路径。

## 上服务器前先确认 4 件事

部署前先问项目负责人要清楚这 4 件事：

1. `deepseek_api_key`
2. `qwen_api_key`
3. 本次对外访问口令 `access_password`
4. 服务器公网 IP 或域名，以及 8506 端口是否能开放

## 最短部署步骤

假设你已经登录到一台 Linux 服务器。

### 1. 把包传到服务器

例如放到：

```bash
/opt/zhiweishi
```

如果拿到的是 zip，就先解压：

```bash
mkdir -p /opt/zhiweishi
cd /opt/zhiweishi
unzip zhiweishi_server_handoff_*.zip
cd zhiweishi_server_handoff_*
```

如果拿到的是仓库里的 `prototype/` 目录，就直接进入该目录。

### 2. 准备环境变量

优先用这个精简模板：

```bash
cp server.env.example .env
```

然后编辑 `.env`，至少填这几项：

```bash
deepseek_api_key=你的DeepSeek Key
qwen_api_key=你的Qwen Key
access_password=你们这次要用的口令
PUBLIC_APP_MODE=poc1_readonly
```

如果你明确知道这次要跑完整演示版，才把 `PUBLIC_APP_MODE` 改成 `full`。

### 3. 启动服务

```bash
chmod +x deploy_public_server.sh
./deploy_public_server.sh
```

这一步会做两件事：

1. 用 Docker 构建并启动服务
2. 如果包里已经带了索引就直接启动；如果没有就先自动建库

### 4. 打开页面

部署成功后，在浏览器里访问：

```text
http://你的服务器IP:8506
```

或者：

```text
http://你的域名:8506
```

首次进入时，页面会先要求输入 `access_password`。

## 你只需要会的 3 个命令

看日志：

```bash
docker compose -f compose.public.yml logs -f
```

重启：

```bash
docker compose -f compose.public.yml up -d --build
```

停止：

```bash
docker compose -f compose.public.yml down
```

## 最容易踩的坑

1. 没有开放服务器的 `TCP 8506` 端口
2. `.env` 里没填 API Key
3. `access_password` 留空，导致公网裸开放
4. 把 `PUBLIC_APP_MODE` 改成了 `full`，结果把写入能力也暴露出去

## 交接时的建议分工

你负责的重点其实只有两件事：

1. 让页面稳定跑起来
2. 把可访问地址返回给项目负责人

知识库内容、问答效果和演示口径，不是你这次部署任务的重点。

## 一句结论

如果你要把这个原型挂到服务器上，最短做法就是：拿到部署包后进目录，`cp server.env.example .env`，填 key 和口令，再执行 `./deploy_public_server.sh`。
