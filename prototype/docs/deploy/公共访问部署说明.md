# 公共访问部署说明

这份说明只回答一个问题：如果不想让组员自己配环境，能不能由你这边统一开一个公共入口，让大家直接访问？

答案是：可以，而且这比把一整套程序和 API 配置发给每个人更稳。

## 最推荐的思路

当前阶段最推荐的不是把原型打包发给每个人，而是：

1. 由你自己的电脑或一台固定服务器统一托管。
2. 运行 `PoC1 只读模式`。
3. 配一个访问口令。
4. 其他人只通过浏览器访问。

这样做的好处是：

1. API Key 只保留在你这一台机器上。
2. 组员不需要装编辑器、Python 或依赖环境。
3. 你可以随时切换知识库和演示版本，不需要大家分别更新。

## 两种可行方案

### 方案 A：你自己的电脑直接对外共享

适合短期试用或现场 PoC。

做法：

1. 你自己的电脑先配好 `.env` 和索引。
2. 运行 `start_poc1_readonly.bat`。
3. 把终端显示的局域网地址发给其他人。

如果需要跨网络访问，可以再配合公网转发工具或临时隧道服务。

### 方案 B：开一台固定公共服务器

适合需要让组员持续访问，不依赖你本人电脑一直开着。

做法：

1. 在服务器上部署当前原型。
2. `.env` 中设置：

```bash
app_mode=poc1_readonly
access_password=你自己设定的口令
```

3. 在服务器上启动：

```bash
uv sync
uv run python build_knowledge_base.py
uv run streamlit run app.py --server.address 0.0.0.0 --server.port 8506
```

4. 把服务器域名或公网 IP 发给大家。

## 为什么不建议直接分发“完整 app”

因为你现在的核心目标只是让大家能访问和体验，不是让每个人都维护一套运行环境。直接分发完整包的问题在于：

1. API Key 安全性差。
2. 每台机器的环境和网络不同，问题会分散到每个人身上。
3. 后续更新知识库或演示版本时，维护成本很高。

## 当前阶段的推荐结论

如果只是给组员试用，最推荐的是：

1. 用 `PoC1 只读模式`
2. 加 `access_password`
3. 由你自己的主机或一台固定服务器统一托管

这已经足够接近一个“大家都能访问的 app”了，只是它运行在你的主机或服务器上，而不是分发到每个人手里。
