# 组员试用说明

这份说明只对应一件事：让组员先把原型打开，亲手试一下 PoC1 的故障排查流程。

## 最推荐的方式

最省事的方式不是每个人都装一套环境，而是由一台主机先启动服务，其他人通过浏览器访问这台主机。

如果你本人会到 PoC 现场，这也是最推荐的做法。你自己的电脑负责跑原型、保管 API Key 和索引，其他组员只负责打开浏览器使用，不需要装代码编辑器，也不需要配 Python 环境，更不需要接触 API 配置。

## 先由一台主机准备好

第一次使用前，主机上需要先做一次准备：

```powershell
cd prototype
uv sync
Copy-Item .env.example .env
uv run python build_knowledge_base.py
```

然后在 `.env` 里填好 API Key。

## 如果只是给组员体验 PoC1

直接双击：

```text
start_poc1_readonly.bat
```

脚本启动后会自动：

1. 打开本机浏览器。
2. 在终端里显示本机访问地址。
3. 在终端里显示可用的局域网访问地址，方便你直接发给其他人。

这个模式下：

1. 只保留故障排查、项目概览、测试集。
2. 不显示案例回写和数据导入。
3. 不会误触写入操作。

默认访问地址：

```text
http://localhost:8506
```

## 如果要完整演示

直接双击：

```text
start_full_demo.bat
```

这个脚本也会自动打开浏览器，并在终端里显示可共享的访问地址。

这个模式会保留完整页面，包括案例回写、培训模式和数据导入。

默认访问地址：

```text
http://localhost:8507
```

## 其他组员怎么连

如果现场大家连的是同一个局域网，其他人可以直接在浏览器里打开：

```text
http://主机IP:8506
```

或者完整模式：

```text
http://主机IP:8507
```

例如主机 IP 是 `192.168.1.23`，那别人就打开：

```text
http://192.168.1.23:8506
```

最重要的前提是：主机和其他组员必须能互相访问。

通常有两种稳妥方式：

1. 大家连同一个路由器或同一个局域网。
2. 由主机自己开热点，其他人连这台主机的热点。

如果用的是学校或公共场地 Wi-Fi，要注意有些网络会做终端隔离。表面上大家都连上了同一个 Wi-Fi，但设备之间不能互相访问。这种情况下，最稳的做法反而是主机自己开热点。

## 什么时候适合用哪一种

1. 只是让组员试 PoC1：用 `start_poc1_readonly.bat`
2. 你自己演示完整闭环：用 `start_full_demo.bat`

## 如果别人连不上

优先检查这 4 件事：

1. 主机和其他组员是不是在同一个网络里。
2. 主机上的脚本是不是已经启动成功。
3. 别人访问的是不是主机 IP，不是 `localhost`。
4. Windows 防火墙有没有拦截对应端口。

## 一句结论

PoC1 试用最推荐的方式，就是一台电脑启动只读模式，其他组员通过浏览器连这台电脑。

## 关于“直接做成 app”这件事

技术上可以继续往下做，比如把当前原型再包装成更像桌面程序的形式。但对你现在这个阶段来说，不推荐把“带着你自己的 API Key 和配置”的独立包直接发给别人，因为：

1. API Key 会跟着包一起出去，安全性差。
2. 每台机器的网络和兼容性都不一样，反而更容易出问题。
3. 你现在的核心目标只是让组员能体验 PoC1，不是让每个人维护一套环境。

所以更稳的做法不是“每个人都有一个 app”，而是“你这台主机就是 app，其他人只连你的浏览器地址”。

## 如果不在同一个局域网怎么办

如果组员不在同一个局域网里，但你又不想租服务器，可以直接用：

```text
start_poc1_public_tunnel.bat
```

它会基于系统自带的 `ssh` 建一个临时公网访问地址。更具体的用法见 [临时公网隧道试用说明.md](./临时公网隧道试用说明.md)。
